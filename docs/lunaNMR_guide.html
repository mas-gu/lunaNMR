LunaNMR v1.0 — How It Works

A professional NMR peak analysis & integration suite (PySide6/Qt6). This guide explains the architecture, the fitting algorithms, the series/titration pipeline, and the analysis modules.
PySide6 / Qt6Voigt fitting PS2D 2D deconvolutionTitration / Kd DynamiXs relaxation

Overview

LunaNMR detects, fits, and integrates peaks in 2D NMR spectra (primarily ¹H–¹⁵N / ¹H–¹³C HSQC), then tracks them across a series of spectra to extract quantitative observables — relaxation rates, binding affinities (Kd), chemical-shift perturbations (CSP), and intensities.

Detect

Network-clustered peak picking with prominence analysis and quality assessment.

Fit

Professional Voigt profiles (Gaussian + Lorentzian) with ArPLS baseline correction; 2D simultaneous deconvolution of overlapping clusters (PS2D).

Track

Cascade propagation across a series so moving peaks (titration) stay locked to the right signal.

Analyze

DynamiXs (T1/T2, methyl T2, model-free) and a Kd/titration module (CSP + intensity binding fits).

The active, production codebase is lunaNMR_v1o0/ (released at github.com/mas-gu/lunaNMR).

Install & launch

cd lunaNMR_v1o0/
pip install -r requirements.txt
python3 lunaNMR/validation/verify_installation.py   # verify
python3 launch_lunaNMR.py                            # run
python -m pytest tests/                              # tests

Key dependencies: numpy, pandas, scipy, scikit-learn, networkx, matplotlib (backend forced to QtAgg), nmrglue, PySide6 ≥ 6.6 (required), numba (required — 3–5× faster 2D fitting; without it large clusters are impractical). Optional: PyTorch (CNN peak classifier).

The workflow

Load spectrum→ Detect peaks→ Voigt fit / PS2D→ Series fit (cascade)→ Output CSVs→ Analysis module

A single spectrum is loaded, peaks are detected and fitted. For a series (relaxation delay or ligand titration), the reference spectrum is fitted first, then every other spectrum is fitted by propagating the reference peak positions forward. The series produces a set of CSV outputs that the analysis modules (DynamiXs, Kd) consume.

GUI framework

Entirely Qt6 via PySide6. The launcher uses tkinter only for the app-selector dialog. The matplotlib backend is forced to QtAgg before any matplotlib import (critical for NavigationToolbar2QT compatibility). The main window LunaNMRMainWindow(BaseWindow) lives in gui/main_window.py; all dialogs inherit BaseDialog(QDialog); styles load from gui/styles/main.qss. Long-running work (peak detection, series fits, module fits) runs on QThread workers to keep the UI responsive.

Logging

Unified routing via utils/output_manager.py: log_progress / log_info / log_warning / log_error. In GUI mode messages route to a dialog log area; in CLI mode they fall back to print(). Thread-local callbacks isolate parallel workers.

Peak detection

core/enhanced_peak_picker.py uses network-based clustering (via networkx) with prominence analysis for robust detection, then quality assessment with R² and uncertainty. Detection supports manual region restriction and nucleus-adaptive search windows. An optional CNN classifier (ml/cnn_peak_classifier.py, PyTorch) can filter candidate peaks.

Voigt fitting

core/enhanced_voigt_fitter.py fits a Voigt profile (convolution of Gaussian and Lorentzian) to each peak's 1D cross-sections, with ArPLS baseline correction (Asymmetrically Reweighted Penalized Least Squares). Overlapping peaks are handled by multi-peak deconvolution — simultaneously fitting neighbours rather than one at a time.

core/core_integrator.py (EnhancedVoigtIntegrator) is the master orchestrator: it runs detection, centroid refinement, overlap clustering, and decides whether a cluster needs the 2D PS2D path or a 1D cross-section fit.

PS2D — 2D simultaneous multi-peak fitting

When peaks are too close for 1D cross-sections to separate them, LunaNMR fits the full 2D region with all overlapping peaks at once. This is an exact port of the C++ PINT algorithm.

When it triggers

Automatically when peaks are separated by < 0.08 ppm (¹H) or < 0.8 ppm (¹⁵N). Typical gain: 1D cross-section fit R² ≈ 0.84 → 2D fit R² ≈ 0.90, position accuracy < 10 ppb.

Clustering (critical)

identify_overlap_clusters() is called once before fitting and builds hierarchical, graph-based clusters with transitive overlap: if A overlaps B and B overlaps C, then {A,B,C} form one cluster. Clusters are disjoint — each peak appears in exactly one — and respect diameter and max-size limits from ps2d_config.py. This is not a simple radial search; it uses full connectivity analysis.

Parameter normalization

ps2d_style_fitter.py normalizes every parameter to O(1) via scales = max(|params|, 1e-8), dropping the Hessian condition number from ~10¹⁰ to ~10³–10⁴. The Jacobian is chain-ruled (J_norm = J_phys · scales) and the covariance denormalized (cov · outer(scales, scales)).

Two-pass linewidth learning

Pass 1: fit all isolated peaks, collect median linewidths and L/G ratios. Pass 2: apply those statistics as initial guesses for multi-peak clusters (threshold R² > 0.85, ≥ 3 good fits, else fall back to config defaults).

5-stage Levenberg-Marquardt: (0) intensity-only, (1) linewidths, (2) positions, (4) global. Hard position bounds are enforced via np.clip() every iteration. Falls back to 1D cross-sections if 2D fitting fails.

Parallel processing

core/parallel_voigt_processor.py distributes whole clusters (not individual peaks) across worker processes after identify_overlap_clusters() has run once — so sequential and parallel modes produce identical results. ≈2.7× speedup on 6 cores (~120 s → ~45 s for 150 peaks). Failed fits always emit a placeholder so the result list stays 1:1 with the peak list (index alignment that downstream cascade tracking depends on).

Series — time-series vs titration

A series fit processes many spectra that share a peak list. The mode determines the x-axis and the tracking policy:

Time-series (relaxation)Titration
PeaksStay putMove (fast exchange)
x-axisRelaxation delay (ms/s)Dimensionless point (e.g. 0, 0.5, 1, 2)
Filename suffix_50ms_0o5 / _1o0 (the o-for-. convention)
TrackingReference positions reused as-isCascade + drift clamp off + wider position margin

The mode is chosen by a dropdown in the series-integration dialog (off / time series / titration), threaded through DelayExtractor(mode=...). The titration path is purely additive — the time-series path is unchanged.

Cascade tracking (titration)

In a titration, interface residues shift while distal ones don't. The cascade fits the reference spectrum, then seeds spectrum N+1 from spectrum N's fitted positions, accumulating drift across the series. The per-step search window scales to the reference linewidth (k = 4 × average LW), and the fit's per-step position bound (pos_margin) is widened in titration mode.

Seed-on-failure

When a peak's fit fails at spectrum N+5, its seed for the next spectrum stays at the last spectrum where a position was actually found (N+4) rather than resetting to the reference. _carry_forward_seed matches peaks by list index (results are peak-ordered and aligned) — not by assignment, because a failed result often carries no assignment.

Margin is human-in-the-loop by design

The position margin can't be fully automated — it's circular (the margin must exceed the per-step shift, which is exactly what's being measured) and per-peak. Too small → R² collapses (loud, self-flagging — fine). Too large → the fit silently grabs a neighbour and returns a confident wrong answer that corrupts the CSP curve. So err toward visible failure; use the overlay viewer's manual edit + refit to fix the few stranded peaks.

Position precision

Fitted positions are written at 4 decimals (≈0.0001 ppm). CSP shifts are ~0.01–0.05 ppm, so any coarser rounding destroys CSP. Series runs from before this fix rounded positions to 0.1 ppm — re-run the series for CSP work. Intensity analysis is unaffected.

Multi-spectrum overlay viewer

Opened from Results Analysis → Multi-Spectrum Overlay Viewer. Contours from any subset of spectra are overlaid, each in its own color. Peak handling:

  • Per-spectrum peak lists: every visible spectrum draws its own fitted-peak markers, colored to match its contour, so overlaid lists are distinguishable. Showing a spectrum auto-enables its peak list; the right-panel Peak lists group toggles each list on/off (a global Show Peak Markers checkbox gates all of them).
  • Manual edit + refit: enable Edit positions, then middle-click a mis-tracked peak and middle-click its true location to set an anchor; Re-fit corrected re-fits each corrected peak across all spectra (cluster-aware, reusing learned linewidths), with undo and save-back to the CSVs.
  • Peak navigator sync: showing/selecting a spectrum updates the peak table to match.

DynamiXs — relaxation analysis

modules/dynamiXs_v2o0/, launched from Modules → DynamiXs Relaxation Analysis. Pages: T1/T2 (mono-exponential), methyl T2 (bi-exponential), spectral density, and Model-Free (integrated).

Methyl T2 (bi-exponential)

Tugarinov–Kay shared-amplitude form I(t) = ½·A·[exp(−t/T2a) + exp(−t/T2b)] for ¹³CH₃ groups. Fitted internally in the (A, T2_avg, ΔT2) basis — not (A, t2a, t2b) — because the (t2a, t2b) basis is degenerate at t2a ≈ t2b and reports nonsense stderrs. ΔT2 ≥ 0 enforces slow-first ordering.

Physical interpretation

T2a (slow) = mI = ±3/2 manifold = TROSY-methyl component — this is what to report as "the methyl T2". T2b (fast) = anti-TROSY. η = T2a/T2b encodes S²axis·τc. T2_avg is an internal fitting coordinate, not a publication observable.

Kd / Titration analysis

modules/dynamiXs_v2o0/dynamiXs_Kd/, launched from Modules → Kd / Titration Analysis (its own dialog — a sibling to DynamiXs, not a DynamiXs page). Fits binding affinity two ways from a titration series:

Two observables, two different models

ObservableModelNotes
CSPFull 1:1 quadratic isotherm
Δδ = Δδ_max · f_bound(L, P₀, Kd)		 f_bound = ((P+L+Kd) − √((P+L+Kd)² − 4PL)) / 2P. Accounts for protein concentration P₀. CSP = √(ΔδH² + (α·ΔδN)²), α default 0.14.
IntensityNot an isotherm:
I = I_inf + (I₀ − I_inf)·exp(−L/Kd)		 Phenomenological decay (lab convention). I₀ anchors L=0; I_inf is the fitted plateau — peaks keep residual intensity at saturation. The quadratic isotherm does not fit intensity.

Fits are per-residue plus a global shared-Kd CSP fit. Inputs auto-detect the tidy CSV, the tracking CSV, or an intensity matrix. Per-point intensity scales correct for differing scan counts (× height/volume, never positions). The viewer shows per-residue binding curves and Kd-vs-residue bars, with click-to-exclude points + refit.

Always bound Kd ≥ 0

Unbounded curve fitting lands on a degenerate negative-Kd minimum. Every Kd fit bounds Kd ≥ 0. A uniform intensity scale across all points cancels in the I/I₀ ratio — only the difference between one point and the rest (e.g. a half-scan reference) matters.

File formats & persistence

  • Input spectra: Bruker TopSpin (.2rr/.2ii), Varian/Agilent (.fid/.ft), NMRPipe (.ft/.pipe), Sparky (.ucsf) — via nmrglue.
  • Projects: .lunaNMR bundle files for state-based save/load (utils/project_manager.py).
  • Decimals convention: filesystem-safe o-for-. in titration filenames (1o0 = 1.0), shared with the dynamiXs parsers.

ML subsystem (optional)

A dual-path predictor with graceful fallback: decision_engine.py chooses between an ML predictor (ml_predictor.py) and a statistical fallback (stats_predictor.py) for fit parameters. An adaptation_engine.py refines the model from user corrections, surfaced through the standalone ML Learning Center. The CNN peak classifier requires PyTorch and is optional.

Gotchas & design principles

Silent failure > visible failure

Prefer a fit that fails loudly (low R²) over one that confidently grabs a neighbour and corrupts data. Don't inflate margins to catch the last movers — fix those by hand.

Bound Kd ≥ 0

Unbounded fits find a degenerate negative-Kd minimum.

CSP needs fresh runs

Positions are now 4-decimal; older runs rounded to 0.1 ppm and can't do CSP. Intensity is fine on old data.

List alignment

Failed fits emit placeholders so result lists stay 1:1 with the peak list — cascade carry-forward matches by index.

numba required

Without it, large 2D clusters take minutes instead of seconds.

QtAgg first

Force the matplotlib backend before any matplotlib import.
