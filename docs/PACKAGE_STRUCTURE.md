# Package Structure – lunaNMR v0.9

This guide captures the current layout of `lunaNMR_v0o9`, summarising what lives where and how contributors should navigate the repository.

## 1. Top-Level Overview

```
.
├── launch_lunaNMR.py         # Launcher for LunaNMR + optional DynamiXs module
├── README.md
├── docs/                     # Guides, architecture notes, contributor information
├── requirements.txt          # Runtime dependencies (Numba, NumPy, etc.)
├── data_example/             # Sample spectra used in docs/tests
├── ml_training_data/, batch_ml/  # Generated ML artefacts (optional)
├── report/, test_ml_output/  # Analysis outputs (git-ignored by default)
└── lunaNMR/                  # Primary Python package
```

## 3. Optional Modules

`modules/` provides a parking lot for independent applications. `modules/dynamiXs/` integrates the DynamiXs relaxation toolkit. Update `launch_lunaNMR.py` if you add new entries to the launcher.

## 4. Supporting Data & Outputs

- `data_example/` – curated HSQC, relaxation, and 1D spectra for demos.
- `ml_training_data/`, `batch_ml/`, `test_ml_output/` – generated by batch pipelines; safe to clean between runs.
- `report/` – notebooks or artefacts from experimentation (ignored by git).

## 5. Coding Guidelines Snapshot

- Keep new engines in `lunaNMR/core/` and expose them via existing processors.
- Share configuration via `utils/parameter_manager.py` (or the simplified adapter) so GUI and batch paths stay aligned.
- Store long-form docs in `docs/` and link to them from `README.md` when introducing major features.

## 6. When to Update This Document

- You add/remove directories, rename modules, or change public entry points.
- You introduce new optional modules or ML collectors.
- You restructure outputs that users need to be aware of.

Maintaining this map helps new contributors orient themselves quickly.
